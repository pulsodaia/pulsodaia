# triade-bot-builder

Skill que monta **estrutura completa de bot Conversation AI** no GoHighLevel: bot + pipeline + workflows + calendarios + KB + dashboard. Combina o **snapshot Triadeflow oficial** (link `XgMan1AGLtLWMGfcttaJ`, validado na subconta Clara Estetica) com o **bot Mariah real** (validado em prod na Amo Sobrancelhas).

## Princípio

Skills sao procedurais. Agentes sao executores. Esta skill **explica como** construir bot + estrutura completa e disponibiliza materia prima. Quem **executa** eh o `@convo` (persona Conversation AI Architect entregue na aula 01).

## Workflow padrao (7 passos pra construir bot do zero)

### 1. Briefing
Pegar do `@revops` ou direto do cliente:
- Nicho exato (estetica facial, depilacao, sobrancelhas, odonto, etc)
- Canais (WhatsApp, IG, FB, SMS, Web Chat, Voice)
- Intent principal (qualificacao, agendamento, FAQ, recompra)
- Ticket medio (impacta agressividade do prompt)
- Volume mensal esperado (impacta pricing)
- Politica de cancelamento + horario de funcionamento

### 2. Escolher template RTG base
Ver `templates-rtg/`. Validado em prod: `clinica-estetica.md`. [BETA]: `odonto.md`, `cosmeticos-recompra.md`, `consultoria-b2b.md`. Pra nicho novo, pegar o mais proximo e ajustar.

### 3. Preencher Knowledge Base
Ver `knowledge-base/kb-format-generico.md`. Estrutura padrao: 3-5 URLs (servicos, contato, politicas) + 5-8 Q&A (objecoes comuns) + edge cases (cancelamento, segunda visita, contra-indicacoes).

### 4. Escolher Flow Builder patterns
Ver `flow-builder-patterns/`. Padrao Triadeflow ativa por default:
- `horario-fechado.md` sempre
- `cancelamento-escala-humano.md` sempre
- `3-tries-fallback.md` sempre
- `vip-bypass.md` se cliente tem segmentacao VIP

### 5. Criar bot via API
Ver `api-reference/create-agent-via-api.md`. Endpoint: `POST /conversation-ai/agents` com PIT da subconta (caminho com hifen, sem `al`). Attach actions: confirmar via UI ou via `PUT /conversation-ai/agents/{id}` (endpoint `/actions` retorna 404).

Alternativa UI: cobrir tudo manual em Conversation AI > Bots > Create New.

### 6. Bot Trial
Ver `playbook/bot-trial-checklist.md`. 10 cenarios obrigatorios antes de subir do modo OFF.

### 7. Graduacao OFF -> Suggestive -> Auto-Pilot
Ver `playbook/graduacao-off-suggestive-auto.md`. Regra: 1-2 semanas Suggestive antes de subir pra Auto-Pilot. Criterios de salto e de retorno explicitos.

## Convencoes Triadeflow embutidas

- **Sem em-dash** em qualquer resposta do bot (cliente final percebe IA). Usar virgula, ponto, hifen normal.
- **Sem promessa de prazo** sem confirmar agenda (bot agenda condicional)
- **Sempre confirmar** dados antes de marcar (paciente diz "amanha 14h", bot repete "confirma quarta 18/05 14h?")
- **Tom calmo profissional** (modelo Mariah, validado em prod)
- **Nunca prometer resultado clinico** (especialmente estetica e odonto, regra CFM se aplicavel)
- **Discovery antes de criar** (ver `triade-ghl-mastery` - sempre GET o existente antes de POST novo)

**Trigger:** appointment booked

4. Wait until 2h antes
5. Send reminder final + opcao de cancelar/remarcar

### Fluxo 01 - Criando oportunidade

**Trigger:** Contact created OU Tag added "lead-novo"
**Acoes:**
1. Create opportunity in pipeline "Clara IA - Estetica"

**Trigger:** Calendar event created OU bot action appointmentBooking
**Acoes:**
1. Move opportunity to stage "Agendado"
2. Add tag "warm lead" (se nao tiver)
3. Trigger "Confirmação de Agendamento + Lembrete"

### Fluxo 03 - Nao Fechou

**Trigger:** Opportunity stage = "IA Atendendo" AND idade > 24h sem agendamento
**Acoes:**
1. Move opportunity to stage "Nao Fechou"
2. Add tag "follow-up"
3. Trigger "Fluxo 04 - Follow-up"

### Fluxo 04 - Follow-up

**Trigger:** Tag added "follow-up"
**Acoes:**
1. Wait 3 dias
2. Send message: "Oi, ainda interessada em {procedimento}?"
3. Wait 4 dias
4. Send message: "Estamos com horario disponivel essa semana"
5. Wait 7 dias
6. Send message final: "Posso te ajudar com algo?"
7. Apos 14 dias sem resposta: move pra stage "Perdido" (se houver) ou archive

### Fluxo 05 - Processo de Follow-up

**Provavelmente:** wrapper que orquestra o "Fluxo 04 - Follow-up" + branching condicional baseado em resposta.

### Fluxo 06 - Oportunidade Ganha

**Trigger:** Opportunity status = "won" OU bot detectou "cliente atendido"
**Acoes:**
1. Move opportunity to stage "Procedimento Realizado"
2. Add tag "procedimento realizado"
3. Trigger NPS workflow (D+1)
4. Add to workflow "Reativacao 30d"

### Fluxo 07 - EU QUERO

**Inferencia:** lead que disse "eu quero" / "quero agendar agora" pula etapas de qualificacao.
**Trigger:** Tag "lead-quente" OU palavra-chave detectada
**Acoes:**
1. Skip qualificacao
2. Send agenda link direto
3. Tag "high priority"

### SHOW e NO SHOW

**Trigger:** Calendar event ended
**Branching:**
- Branch SHOW: Move pra "Procedimento Realizado", trigger NPS
- Branch NO SHOW: Move pra "NAO COMPARECEU", trigger recuperacao

Estrutura padrao pra qualquer bot Conversation AI no GHL, independente de nicho. Use quando construir bot pra cliente novo.

Uma Knowledge Base eh composta por **Knowledge Sources**. Cada source eh um dos 5 tipos:

| Tipo | Quando usar | Limite tipico |
|------|-------------|---------------|

| **Table (planilha)** | Lista estruturada (servicos, precos, horarios) | 1-3 tabelas |

### Layer 1: Identidade
- Nome do negocio
- Localizacao (endereco, cidade, regiao)
- Telefone e email principais
- Site
- Redes sociais (so se relevante)

### Layer 2: Servicos
- Lista de servicos/produtos com descricao curta
- Faixa de preco (NUNCA valor exato)
- Duracao tipica

- Horario de funcionamento (por categoria de servico se variar)
- Politica de cancelamento
- Politica de pagamento (formas, parcelamento)
- Politicas especificas do nicho (gestantes, contraindicacoes, idade minima)

### Layer 4: Q&A diretas
- Aceita cartao?
- Tem estacionamento?
- Atende menor de idade?
- Atende fim de semana / feriado?
- Aceita convenio / desconto?
- Tem WiFi?
- Posso levar acompanhante?
- (8-15 perguntas frequentes do nicho)

## Custom Tools (avancado)

Custom Tools sao webhooks que o bot dispara em runtime. Ex: a Mariah dispara `consultar_servicos` quando cliente pergunta preco.

Estrutura de Custom Tool:

```yaml
name: consultar_servicos
description: Retorna lista completa de servicos da clinica com categoria, preco e duracao

  url: https://services.leadconnectorhq.com/hooks/{location_id}/{tool_id}
  method: POST
  headers:
    Authorization: Bearer {pit_token}
schema:
  input: {} # geralmente vazio
  output:
    servicos:
      - categoria: string
        nome: string
        preco_a_partir: number
        duracao_min: number
```

Custom Tools sao **manuais de configurar via UI** (API nao expoe gestao de KB em Maio/2026). Mas o webhook em si pode ser construido programaticamente.

A KB carrega no contexto do bot baseado em regras:

- `all` - sempre carrega (default Mariah)

# Flow Builder Pattern - Cancelamento Escala pra Humano

Quando cliente fala em CANCELAR, o bot NAO tenta reverter. Encaminha direto pra humano. Tentar reverter via IA gera frustracao e perde cliente.

## Logica

```
Trigger: mensagem do cliente
   |
Condition: mensagem contem palavra-chave de cancelamento
   |        regex: \b(cancel|cancela|desmarca|desistir|nao quero mais|adia|remarca)\b
   |
   |--- SIM ---> AI Response curta: "Entendi. Vou chamar uma das meninas pra te ajudar com isso."
   |             |
   |             Action: transferBot (escala pra atendente do time)
   |             |
   |             Action: stopBot (para o bot)
   |             |
   |             END
   |
   |--- NAO ---> segue fluxo normal (AI Response default)
```

## Por que escalar e nao tentar reverter

1. **Cliente ja decidiu.** Discutir gera atrito. Voce ja perdeu a venda nesse momento.
2. **Reagendamento eh oportunidade humana.** Atendente pode entender o motivo, oferecer horario alternativo, propor desconto fidelidade.
3. **Politica de cancelamento eh sensivel.** Cobranca de multa, devolucao de pacote, cancelamento de pagamento parcelado, tudo precisa de humano.
4. **CRM precisa ser atualizado.** Marcar tag "cancelou-em-{data}", atualizar pipeline stage, registrar motivo - tudo isso eh manual.

## Configuracao no GHL Flow Builder V3

Nodes necessarios:

1. **Trigger:** Conversation message received
2. **Condition:** Custom regex check on message body
3. **Branch SIM:** AI Response node (resposta curta) → Action node (transferBot) → Action node (stopBot)
4. **Branch NAO:** continua fluxo principal do bot

## Regex pattern (PT-BR)


# Flow Builder Pattern - VIP Bypass

Cliente VIP (tag aplicada) pula a qualificacao inicial e cai direto em atendimento prioritario (atendente humano OU resposta acelerada do bot).

## Logica

```
Trigger: mensagem do cliente
   |
Condition: contato tem tag = "vip" OU "premium" OU "fidelidade-ouro"
   |
   |--- SIM ---> Branch VIP:
   |             Action: tagContact = "atendimento-prioritario"
   |             |
   |             Decisao:
   |             - Se cliente ja agendou hoje: AI Response "Oi {primeiro_nome}! Confirma o horario das {hora}?"
   |             - Se cliente nao agendou: Action transferBot direto (humano prioritario)
   |
   |--- NAO ---> segue fluxo normal de qualificacao
```

## Quando usar esse pattern

Aplicavel quando o cliente tem **segmentacao clara entre tiers**. Exemplos reais:

| Negocio | Criterio VIP | Tag GHL |
|---------|--------------|---------|
| Clinica estetica | Cliente com pacote ativo | `pacote-ativo` |
| Clinica estetica | Cliente fidelidade | `fidelidade` |
| Odonto | Plano premium | `plano-platinum` |
| Ecommerce | LTV > R$ 5k | `vip-lifetime` |
| Consultoria B2B | Cliente atual (vs prospect) | `cliente-ativo` |

## Por que importa

- VIP nao deve ser qualificado de novo (irritante)
- VIP deve sentir reconhecimento ("voce ja eh nossa cliente, vou direto ao ponto")
- Diferenciacao gera retencao

## Configuracao Flow Builder V3

1. **Trigger:** Conversation message received
2. **Condition:** Contact has tag = "vip" (ou OR list de tags)
3. **Branch SIM:**
   - Action: tagContact (adicionar "atendimento-prioritario")
   - AI Response curta personalizada com `{primeiro_nome}` do contato
   - Decisao: tem agendamento hoje?
     - SIM: confirmar horario
     - NAO: transferBot direto
4. **Branch NAO:** fluxo padrao

## Customizacao por tier

Se o cliente tem multiplos tiers, criar branches:

| Tag | Branch | Acao |
|-----|--------|------|
| `vip-premium` | A | transferBot direto + tag "prioritario-max" |
| `vip-padrao` | B | AI Response acelerada + opcao "falar com gerente" |
| `cliente-ativo` | C | AI Response sem qualificacao, vai pro agendamento direto |
| (sem tag) | D | Fluxo padrao com qualificacao completa |

## Anti-pattern

NAO oferecer "voce eh VIP" em primeira mensagem se cliente nao mencionou. Soa fake. Apenas execute o bypass internamente, o cliente sente a diferenca pelo comportamento.

## Mariah real

## Metricas pra acompanhar

- Taxa de identificacao correta de VIP (precisao da tag)
- Tempo de resposta no branch VIP (deve ser <30s)
- Satisfacao especifica do segmento VIP (NPS isolado)

# Flow Builder Pattern - Horario Fechado

Mensagem fora do horario comercial dispara resposta automatica avisando "respondemos amanha as X horas". Bot NAO tenta atender em pleno funcionamento. Apenas confirma recebimento.

## Logica

```
Trigger: mensagem do cliente
   |
Condition: hora atual NAO esta dentro do horario comercial
   |        (consulta tabela "horarios-funcionamento" da KB ou config do GHL Business Hours)
   |
   |--- SIM (fora do horario) ---> 
   |        AI Response: mensagem padrao com proximo horario util
   |        |
   |        Action: tagContact = "fora-horario"
   |        |
   |        Decisao: ja respondeu fora do horario hoje?
   |        - SIM: nao manda mensagem (evita spam)
   |        - NAO: manda mensagem unica + marca tag "ja-avisei-hoje"
   |
   |--- NAO (dentro do horario) ---> segue fluxo normal
```

- Cliente sente acolhido mesmo fora do horario
- Bot nao toma decisao que precisa de humano (cancelamento, troca, reclamacao) fora do expediente
- Marketing nao perde lead que chega de madrugada
- Atendente humano comeca o dia com mensagem ja respondida

```
Recebido. Respondemos amanha a partir das {HORA_ABERTURA}.
```

# Flow Builder Pattern - 3 Tentativas + Fallback Humano

Apos 3 tentativas consecutivas do bot sem progresso (cliente nao respondeu, bot loopou, ou cliente repete pergunta), escalar pra humano. Evita loop infinito que frustra cliente.

## Logica

```
Trigger: AI Response gerada
   |
Counter: incrementar counter "tentativas-sem-progresso" no contato
   |
Condition: counter >= 3
   |
   |--- SIM ---> 
   |        AI Response: "Vou chamar uma das meninas pra te ajudar diretamente."
   |        |
   |        Action: transferBot
   |        |
   |        Action: stopBot
   |        |
   |        Action: tagContact = "escalado-loop-3-tries"
   |        |
   |        Action: resetCounter "tentativas-sem-progresso" = 0
   |
   |--- NAO ---> bot segue tentando
```

## O que conta como "tentativa sem progresso"

Sinais de loop (qualquer um conta como uma tentativa):

1. **Cliente repetiu pergunta** (similaridade > 80% com mensagem anterior)
2. **Cliente disse "nao entendi"** ou similar
3. **Bot respondeu mas cliente nao reagiu em 30 min** (silencio prolongado)
4. **Bot fez mesma pergunta 2x** (loop interno)
5. **Cliente esta confuso** (regex: "como assim", "nao entendi", "pode explicar de novo", "isso nao faz sentido")

## Configuracao Flow Builder V3

Precisa de **Custom Field no Contato** pra guardar o counter:

| Campo custom | Tipo | Default |
|--------------|------|---------|
| `bot_tentativas_sem_progresso` | Number | 0 |
| `bot_ultima_mensagem` | Text | "" |
| `bot_timestamp_ultima_resposta` | Datetime | null |

Flow:

1. **Trigger:** AI Response generated (bot acabou de responder)
2. **Logica de incremento:**
   - Comparar `current_message` vs `bot_ultima_mensagem` 
   - Se similaridade > 80%: incrementar counter
   - Se cliente disse palavras de confusao: incrementar counter
   - Atualizar `bot_ultima_mensagem` = `current_message`
3. **Condition:** counter >= 3
4. **Branch SIM:** transferir pra humano + resetar counter
5. **Branch NAO:** continua

## Reset do counter

Resetar pra 0 quando:
- Cliente fez agendamento (sucesso)
- Cliente fez pergunta nova e clara (avancou)
- Foi escalado pra humano (tarefa transferida)
- 24h sem nova interacao

## Mensagem de transferencia

```
Vou chamar uma das meninas pra te ajudar com isso direto, ok? Em instantes alguem te responde.
```

Nao dizer "estou tendo dificuldade", "nao consegui te ajudar", "desculpa pela confusao". Cliente nao precisa saber que o bot falhou. Apenas o resultado importa.

## Anti-pattern

NAO escalar antes de 3 tentativas. Bot precisa ter chance real de resolver. Escalacao prematura = custo de atendente humano alto, ROI da IA cai.

NAO escalar SEM resetar counter. Senao, o proximo contato ja entra com counter = 3 e escala imediato.

## Variacao por canal

| Canal | Threshold |
|-------|-----------|
| WhatsApp / SMS | 3 tentativas |
| Web Chat | 2 tentativas (cliente cansa rapido na web) |
| Voice AI | 2 tentativas (audio repetido eh mais frustante) |
| IG / FB | 4 tentativas (canal mais informal, cliente da mais espaco) |

## Metricas

- Taxa de chegada nesse fluxo (ideal: 5-10% das conversas que duram >5 trocas)
- Tempo medio entre primeira interacao e escalacao
- Taxa de "voltou pro bot" apos escalacao humana (raro mas existe)

Se >20% das conversas caem nesse fluxo, o bot esta com prompt ruim ou Knowledge Base incompleta. Revisar antes de aumentar threshold.

Bot detecta via prompt e dispara `transferBot` direto. Funciona pra volume baixo (Amo). Pra volume maior, recomendado configurar counter explicito no Flow Builder pra ter metrica mensuravel.

| `appointmentBooking` | Acopla calendar GHL | Agendar consulta/sessao |
| `tagContact` | Marca tag no contato | Segmentar lead (qualificado, VIP, fora area, etc) |

| `sendNotification` | Notifica usuario do GHL | Alertar dono quando lead alto valor chega |

## Como adicionar Action via UI

Enquanto API de Actions nao for confirmada estavel, recomendado via UI:

1. Conversation AI > Bots > {Bot} > Actions tab
2. + Add Action
3. Escolher type (lista acima)
4. Configurar parametros especificos:
   - `transferBot`: pra qual user/team (se nao escolher, abre pro time)
   - `advancedFollowup`: quando disparar (offset em horas/dias do agendamento)
   - `appointmentBooking`: qual calendar acoplar
   - `tagContact`: qual tag aplicar
5. Save

# Playbook - Graduacao OFF → Suggestive → Auto-Pilot

Bot NUNCA sobe direto pra Auto-Pilot. Sempre passa por OFF (coleta) → Suggestive (humano aprova) → Auto-Pilot (bot responde sozinho).

Mariah real: criada 14/05 em OFF, subiu Auto-Pilot dia 16/05. Volume baixo Amo justificou pular Suggestive prolongado. Pra volume alto, recomendado 2 semanas em Suggestive.

## Os 3 modos

| Modo | O que faz | Quando usar |
|------|-----------|-------------|
| **OFF** | Bot nao responde. So coleta conversa pra voce ler depois | Semana 1 de bot novo. Treinar olho |
| **Suggestive** | Bot sugere resposta pro atendente humano. Humano aprova/edita/envia | Semana 2-3. Validar qualidade |
| **Auto-Pilot** | Bot responde sozinho. Humano so olha relatorio | Producao apos validacao |

## Criterios pra subir de modo

### OFF → Suggestive (apos 1 semana)

Checklist obrigatorio:

- [ ] 30+ conversas reais coletadas no OFF
- [ ] Voce leu pelo menos 10 conversas completas
- [ ] Voce identificou 3+ padroes de pergunta (ex: preco, horario, agendamento)
- [ ] Knowledge Base cobre esses 3 padroes
- [ ] Personality + Goal + Instructions estao alinhados com o tom desejado
- [ ] Action `transferBot` testada (humano recebe quando escala)

### Suggestive → Auto-Pilot (apos 2 semanas)

Checklist obrigatorio:

- [ ] 80%+ das sugestoes do bot aprovadas sem edicao pelo atendente humano
- [ ] 0 incidentes de copy fora do tom (sem travessao, sem promessa falsa, sem "custa")
- [ ] 0 incidentes de info errada (politicas, horarios, precos)
- [ ] Taxa de qualificacao-pra-agendamento > 30%
- [ ] Cliente nao reclamou que "esta falando com robo"
- [ ] Atendente humano confirma: bot esta mais ajudando do que atrapalhando

## Criterios pra voltar de modo (importantissimo)

### Auto-Pilot → Suggestive (recuo cautelar)

Acontece quando bot quebra. Trigger:

- 1 incidente de info errada (preco, horario, promessa)
- Cliente reclama "isso aqui parece bot"
- Taxa de agendamento cai > 20% versus baseline
- Atendente flagra resposta com tom errado (travessao, "custa", "talvez")

Acao: descer pra Suggestive imediato. Revisar prompt. Subir de volta apos 1 semana sem incidente.

### Suggestive → OFF (caso extremo)

- Bot esta sugerindo coisa contraditoria (info errada da KB)
- 3+ incidentes em 1 semana
- Atendente esta gastando MAIS tempo aprovando que escreveria do zero

Acao: voltar pra OFF, reescrever Knowledge Base + Instructions. Subir Suggestive de novo apos validar com Bot Trial.

## Cronograma recomendado

```
Semana 1 (OFF):
- Dia 1-3: instala bot, configura KB, deixa ligado em OFF
- Dia 4-5: le 10 conversas, identifica padroes
- Dia 6-7: ajusta Personality/Goal/Instructions baseado no que viu

Semana 2 (Suggestive):
- Dia 8: sobe pra Suggestive
- Dia 8-10: atendente humano aprova/edita TUDO. Mede % de aprovacao sem edicao
- Dia 11-13: ajusta o que esta sendo editado muito
- Dia 14: checklist de subida pra Auto-Pilot

Semana 3 (Auto-Pilot):
- Dia 15: sobe pra Auto-Pilot se checklist OK
- Dia 15-21: bot responde sozinho. Atendente so olha alertas
- Dia 22: relatorio semanal de qualidade
```

## Casos especiais

### Volume baixo (Mariah/Amo - 5 conversas/semana)

Pode pular Suggestive prolongado. Cronograma adaptado:
- Dia 1-3: OFF
- Dia 4-5: Suggestive
- Dia 6+: Auto-Pilot

Risco: amostra pequena pode esconder padroes ruins. Compensar com revisao manual semanal das primeiras 4 semanas.

### Volume alto (>50 conversas/dia)

NAO encurtar cronograma. Riscos sao maiores (volume amplifica erro). Manter 3 semanas completas.

### Multi-canal (WhatsApp + IG + SMS simultaneo)

Subir 1 canal por vez. Comecar pelo canal de menor volume. Validar 1 semana antes de subir proximo.

## Como medir aprovacao no Suggestive

Custom Field no Contact:

| Field | Tipo | Default |
|-------|------|---------|
| `bot_sugestao_aprovada` | Boolean | null |
| `bot_sugestao_editada` | Boolean | null |
| `bot_sugestao_descartada` | Boolean | null |

Atendente clica em UMA das 3 opcoes ao enviar a resposta. Relatorio agregado por semana.

Meta: 80%+ aprovadas-sem-edicao apos 2 semanas no Suggestive.

- 14/05 01:31 - criada em modo nao especificado (provavelmente nao-OFF dado o volume da Amo)

## Anti-patterns

NUNCA:
- Subir pra Auto-Pilot sem passar pelo Suggestive
- Manter bot em OFF > 2 semanas (perde momentum, cliente acha que ninguem atende)
- Ignorar % de aprovacao no Suggestive (eh o sinal mais importante)
- Descer de modo silenciosamente sem avisar o atendente humano (gera confusao)
- Subir pra Auto-Pilot 2 dias antes de fim de semana ou feriado (sem suporte humano disponivel)

# Playbook - Bot Trial Checklist (10 cenarios)

Bot Trial eh a ferramenta nativa do GHL pra testar o bot ANTES de subir de modo OFF. Rodar 10 cenarios obrigatorios antes de qualquer graduacao.

## Onde abrir o Bot Trial

`Conversation AI > Bots > {Bot} > Test/Trial` (botao no topo da pagina).

Cria uma conversa fake na qual voce simula um cliente. Bot responde como se fosse producao. Sem afetar contatos reais.

## Os 10 cenarios obrigatorios

### 1. Saudacao inicial

```
voce: "oi"
bot: deve responder com saudacao + se apresentar + perguntar como ajuda
```

Validar: tom certo (sem giria, sem travessao), nome do bot e da empresa corretos.

### 2. Pergunta de preco

```
voce: "quanto custa o {servico_principal}?"
bot: deve consultar KB e responder com faixa de preco, NUNCA valor exato
```

Validar: usa "fica em torno de" ou "a partir de", nao usa palavra "custa".

### 3. Pergunta de horario

```
voce: "voces atendem aos sabados?"
bot: deve responder com horario correto da categoria principal
```

Validar: informacao bate com KB. Se horario varia por categoria, bot deve mencionar.

### 4. Pedido de agendamento direto

```
voce: "quero agendar {procedimento_X}"
bot: deve aplicar SCEP (Saudacao, Coleta, Encaminhamento, Proposta)
     - perguntar nome se nao tiver
     - confirmar o procedimento exato
     - mandar link da agenda apos confirmar
```

Validar: bot nao manda link sem confirmar primeiro. Titulo do agendamento eh o nome exato do procedimento.

### 5. Cancelamento

```
voce: "quero cancelar meu agendamento"
bot: deve escalar pra humano imediato, sem tentar reverter
```

Validar: action `transferBot` dispara. Bot nao pergunta motivo, nao oferece desconto, nao tenta reverter.

### 6. Reclamacao

```
voce: "fiquei muito chateada com o ultimo atendimento, a profissional foi grossa"
bot: deve responder com empatia curta + escalar pra humano
```

Validar: NAO pedir mais detalhes, NAO defender a empresa, NAO julgar. Resposta tipo "Sinto muito por isso, vou chamar uma das meninas pra te ajudar."

### 7. Pergunta fora do escopo

```
voce: "voces vendem batom?"
bot: deve responder com gentileza que nao oferece esse servico + sugerir o que oferece
```

Validar: nao usar "nao temos", "nao vendemos" de forma fria. Tom positivo redirecionando.

### 8. Cliente confuso (loop)

```
voce: "nao entendi"
voce: "nao entendi"
voce: "como assim?"
bot: apos 3 tentativas, deve escalar pra humano
```

Validar: 3-tries fallback funciona. Bot nao fica preso em loop.

### 9. Condicao medica grave / contra-indicacao

```
voce: "tenho diabetes grau 3, posso fazer {procedimento_estetico}?"
bot: deve escalar imediato pra humano (NAO dar conselho medico)
```

Validar: bot nao opina sobre saude. Encaminha direto.

### 10. Mensagem fora do horario

```
configurar Bot Trial pra simular hora fora do expediente (ou esperar)
voce: "oi"
bot: deve responder com mensagem padrao de "respondemos amanha as X"
```

Validar: nao tenta atender. So confirma recebimento + horario de retorno.
